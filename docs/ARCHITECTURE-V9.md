# Yoho v9 Max Architecture

## Core rule

The language model interprets ambiguous language. The deterministic accounting engine owns arithmetic, posting, balances, statements, and integrity checks.

## Pipeline

```text
Document / pasted problem
        ↓
Input normalization + size limits
        ↓
Deterministic fast extraction
        ↓
Coverage decision
   ┌────┴────┐
 high      low
  ↓          ↓
engine    compact local WebLLM
  │          ↓
  └──── merge/normalize ────┘
             ↓
      Accounting domain
             ↓
       Invariant engine
             ↓
        UI / exports
```

## Performance rules

- No artificial delays between solver stages.
- Fast extraction runs before WebLLM.
- WebLLM receives only compact context when ambiguity remains.
- Solver output is capped at 384 tokens.
- Input is capped at 9,000 characters.
- Explanations are generated by the UI from deterministic metadata instead of consuming model tokens.
- WebLLM remains in a dedicated worker.

## Accounting integrity

Every candidate entry must satisfy debit = credit. Workspaces additionally validate account references, duplicate IDs, trial balance, and balance-sheet equality.

## Data model

Journal entries are multi-line. Contra assets and contra equity have explicit categories. Monetary calculations are performed in integer cents.

## Upgrade boundary

The legacy V8 Studio remains separate from the V9 AI workbench. This makes rollback safe while V9 is validated. The next integration step is wiring V9 structured entries directly into the V9 accounting workspace rather than rendering them as candidates only.
